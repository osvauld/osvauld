# Osvauld Extended Web: Exploratory Engineering Whitepaper (Draft 0)

## Preface

At its core, the internet is about reading verified information, collaborating with others, chatting, exchanging files, ordering services, hosting offerings, and discussing ideas.

Today, intermediaries control these activities: their algorithms, their feeds, their rules, their infrastructure.

The Extended Web extends the internet so you control these activities. Applications live on your devices and sync through your node. Your cryptography defines permissions. Your designs determine the experience. The fundamentals stay the same, but they are extended to give you sovereignty over your digital life.

## 1. Problem Framing and System Thesis

The thesis is not "replace the internet." The thesis is "extend the internet's application model" from platform-controlled coordination to sovereign coordination.

Engineering interpretation:

- State should commit locally first (offline-first correctness).
- Sync should be asynchronous and convergent (CRDT semantics, not transactional request-response).
- Authorization should be portable and verifiable from signed capabilities, not mutable centralized ACL rows.
- Coordination infrastructure can exist (nodes), but it is user-run sovereign infrastructure, not mandatory platform centralization.

## 3. Data Model, Sharding, and Memory Efficiency

### 3.1 Core Data Model

State hierarchy is Identity -> Space -> Page -> Layer. Layers are the practical unit of replication, authorization, and memory residency.

### 3.2 Critical Claim: Sharding Reduces Memory Consumption

Engineering rationale for this claim:

- Monolithic layer growth increases resident CRDT working set and UI model pressure.
- Layer-native sharding (for example time sharding by day/minute) bounds active read/write windows.
- Selective subscription and per-layer sync reduce in-memory residency of irrelevant partitions.

Where this is declared:

- Whitepaper draft examples (`messages/{YYYY-MM-DD}`, minute/day resolutions): `docs/WHITEPAPER_DRAFT.md`
- `.osv` time sharding declarations: `osv_decl/src/ast.rs`, `osv_decl/src/parser.rs`, `docs/app-dev/APP_OSV_GRAMMAR.md`

### 3.3 LayerUnit as In-Memory Efficiency Boundary

Working hypothesis for exploratory draft:

- `LayerUnit` encapsulates per-layer residency, dirty tracking, observer subscription, subscriber vector state, and sync behaviors.
- This likely makes memory behavior compositional per layer instead of globally monolithic per page document.
- In practice, this is the mechanism that can make sharding operationally useful for memory.

Important caveat: declared controls (`Hot/Cold`, retention, cache hints) may not all be equally enforced at runtime today.

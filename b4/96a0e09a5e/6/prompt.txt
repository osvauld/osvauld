# Plan: LayerAccessPolicy — Foundational Layer Authorization

## Context

The dynamic layer authorization system was bolted onto the existing static layer protocol as an afterthought. The result:

- **11 call sites** populate `authorized_dids: HashSet<String>` on each LayerUnit — subscription, layer creation (7 paths), AuthorizeLayerSubscriber, pending authorizations, explicit access grants
- **Complex wire protocol chain**: `emit_dynamic_layer_permits` → `SyncEvent::NewDynamicLayer` → Coordinator → PeerActor → `LayerPermitMsg` → `on_layer_permit` → `AuthorizeLayerSubscriber` → `pending_layer_authorizations` — all to add one DID to a HashSet
- **Race conditions**: `pending_layer_authorizations` exists only because `AuthorizeLayerSubscriber` can arrive before the layer is created
- **Bugs**: Viewer writes to dynamic channels fail silently because the node never gets added to `authorized_dids` on the viewer's Scribe

**Root cause**: `authorized_dids` is a cache that's populated eagerly from multiple disconnected sources with no single source of truth.

**Solution**: Replace ad-hoc `authorized_dids` with a first-class `LayerAccessPolicy` on each LayerUnit. Authorization is computed at broadcast time from the policy + subscriber info, not pre-populated.

## Design: LayerAccessPolicy

### The enum

```rust
// scribe/src/layer_unit/mod.rs

/// How access is determined for this layer — set once at creation, checked at broadcast time.
/// This replaces the ad-hoc authorized_dids HashSet that was populated from 11 call sites.
pub enum LayerAccessPolicy {
    /// Static layer: access by subscriber's page permit
    /// e.g., channels/general/messages, app:Group Chat
    PagePermit,

    /// Role-based dynamic layer: access by role match against schema
    /// e.g., channels/did:key:alice/project-x/messages (grant: "role")
    /// All collaborators/owners with matching roles get access automatically
    RoleBased {
        allowed_roles: HashSet<String>,
    },

    /// DID-based dynamic layer: access by explicit DID set
    /// e.g., dms/did:key:alice/room1/messages (grant: "explicit")
    /// Only specifically granted DIDs get access
    Explicit {
        authorized_dids: Arc<RwLock<HashSet<String>>>,
    },
}
```

### The broadcast check (used by observer AND broadcast_update)

```rust
fn can_broadcast_to(
    access_policy: &LayerAccessPolicy,
    subscriber_did: &str,
    subscriber_info: &SubscriberInfo,
    layer_name: &str,
    page_id: &str,
    sync_target: Option<&str>,
) -> bool {
    // Rule 1: Sync target always receives ALL syncable layers
    // This is the owner/viewer → node path. The node is our sync target.
    if sync_target == Some(subscriber_did) {
        return true;
    }

    // Rule 2: Check the layer's access policy
    match access_policy {
        LayerAccessPolicy::PagePermit => {
            subscriber_info.can_receive_layer(layer_name, page_id)
        }
        LayerAccessPolicy::RoleBased { allowed_roles } => {
            let role = subscriber_info.permit.relationship().unwrap_or("peer");
            allowed_roles.contains(role)
        }
        LayerAccessPolicy::Explicit { authorized_dids } => {
            authorized_dids.read()
                .map(|set| set.contains(subscriber_did))
                .unwrap_or(false)
        }
    }
}
```

**Key insight**: The `sync_target` rule is why viewer writes work. The viewer's Scribe always broadcasts to the node (its sync_target) regardless of access policy. No LayerPermit chain needed.

### Setting the policy (replaces 11 call sites)

Every layer creation path sets the policy once:

```rust
fn determine_access_policy(
    layer_name: &str,
    our_permit: Option<&gurkha::Permit>,
    page_id: &str,
) -> LayerAccessPolicy {
    if let Some(permit) = our_permit {
        if let Some((_key, schema, _creator)) = find_matching_dynamic_schema(permit, layer_name, page_id) {
            return match schema.grant {
                GrantType::Role => LayerAccessPolicy::RoleBased {
                    allowed_roles: schema.role_permissions.keys().cloned().collect(),
                },
                GrantType::Explicit => LayerAccessPolicy::Explicit {
                    authorized_dids: Arc::new(RwLock::new(HashSet::new())),
                },
            };
        }
    }
    LayerAccessPolicy::PagePermit
}
```

## The three access patterns

### Pattern 1: Static layer (PagePermit)
```
page.lua:  layer("channels/general/messages", ...)
permit:    layers: { "channels/general/messages": { sync: true, write: true } }

→ LayerAccessPolicy::PagePermit
→ Broadcast check: subscriber.permit.can_read_layer("channels/general/messages")
→ No wire protocol needed beyond initial sync
```

### Pattern 2: Role-based dynamic layer (RoleBased)
```
page.lua:  layer("channels/{channel_id}/messages", ..., { grant = "role" })
permit:    dynamic_layer_schemas: { "channels/{id}/messages": { role_permissions: {owner, collaborator, node} } }

→ LayerAccessPolicy::RoleBased { allowed_roles: {owner, collaborator, node} }
→ Broadcast check: allowed_roles.contains(subscriber.role)
→ No LayerPermit wire protocol needed
```

### Pattern 3: DID-based dynamic layer (Explicit)
```
page.lua:  layer("dms/{id}/messages", ..., { grant = "explicit" })
permit:    dynamic_layer_schemas: { "dms/{id}/messages": { grant: "explicit" } }

→ LayerAccessPolicy::Explicit { authorized_dids: {} }
→ Broadcast check: authorized_dids.contains(subscriber_did)
→ Node issues LayerPermit when creator calls add_layer_access(did)
→ AuthorizeLayerSubscriber adds DID to the set
```

## How the bugs are fixed

### Bug: Viewer writes to dynamic channel
**Before**: Node not in `authorized_dids` on viewer's Scribe → observer skips → message never sent.
**After**: Node is viewer's `sync_target` → always receives broadcasts. No `authorized_dids` check needed.

### Bug: Late joiner
**Before**: `emit_dynamic_layer_permits` doesn't fire (layer already exists), `fanout_sync_meta` handles discovery but authorization is fragile.
**After**: Viewer connects → subscribes → node's `send_initial_state_to_subscriber` checks `RoleBased` policy → viewer's role matches → data sent. No LayerPermit chain needed.

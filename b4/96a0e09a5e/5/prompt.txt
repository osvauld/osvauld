# JSON Logging & Event Capture System

## Context

We have event systems spread across Courier and Scribe, plus a dormant log capture layer:

| System | Location | Status | Captures |
|--------|----------|--------|----------|
| `CourierEvent` | `courier/src/handle.rs:26` | **Active** | App events: PeerAuthenticated, SpacePublished, ViewerSyncComplete |
| `MessageTrace` | `courier/src/trace.rs` | **Test-only** (None in prod) | Protocol messages: Hello, Welcome with direction + node IDs |
| `PageUpdate` | `scribe/src/message.rs:117` | **Active** | Layer changes, ephemeral, presence, queries |
| `SyncEvent` | `scribe/src/message.rs:180` | **Active** | EnsureSync, NewDynamicLayer, LayerAccessChanged |
| `DebugCaptureLayer` | `logging_utils/src/lib.rs:146` | **Unused** | All tracing log events |

We want a unified capture where script/AI can:
1. `capture_start` on ALL instances → events collected to `.jsonl` files
2. Run operations
3. `capture_end` → per-instance files merged for AI analysis

**Default**: CourierEvents + MessageTraces + PageUpdates + SyncEvents (structured events only).
**Optional**: `include_logs=true` adds tracing logs.

## Architecture

```
Python Script / AI
  │
  ├─ client.capture_start("/path/file.jsonl")
  │   └─→ Control Server → CaptureHandle.start()
  │        ├─ Subscribes to CourierEvent broadcast
  │        ├─ Subscribes to MessageTrace broadcast
  │        ├─ Subscribes to PageUpdate broadcast
  │        ├─ Subscribes to SyncEvent broadcast
  │        └─ (if include_logs) Subscribes to DebugLogEntry broadcast
  │
  ├─ <operations happen>
  │
  └─ client.capture_end()
      └─→ CaptureHandle.stop() → flush → file ready
```

### JSONL Output Format
```json
{"type": "courier_event", "ts": "...", "name": "PeerAuthenticated", "data": {...}, "instance": "owner"}
{"type": "message_trace", "ts": "...", "direction": "Sent", "msg": "Hello", "node_id": "...", "instance": "node"}
{"type": "page_update", "ts": "...", "name": "LayerChanged", "page_id": "...", "data": {...}, "instance": "owner"}
{"type": "sync_event", "ts": "...", "name": "EnsureSync", "data": {...}, "instance": "node"}
{"type": "log", "ts": "...", "level": "INFO", "target": "courier::coordinator", "msg": "...", "instance": "owner"}
```

**New**: `CaptureHandle` struct — generic over event sources:
```rust
#[derive(Clone)]
pub struct CaptureHandle {
    log_tx: broadcast::Sender<DebugLogEntry>,
    /// Set after courier/scribe init via register methods
    capture_sources: Arc<RwLock<CaptureSources>>,
    cancel_tx: Arc<Mutex<Option<oneshot::Sender<()>>>>,
    instance_name: String,
}

struct CaptureSources {
    courier_event_tx: Option<broadcast::Sender</* CourierEvent */>>,
    message_trace_tx: Option<broadcast::Sender</* MessageTrace */>>,
    page_update_tx: Option<broadcast::Sender</* PageUpdate */>>,
    sync_event_tx: Option<broadcast::Sender</* SyncEvent */>>,
}
```

Since `logging_utils` can't depend on `courier` or `scribe` (circular), `CaptureHandle` uses a trait or generic serialization approach:
- Option A: `CaptureHandle` accepts `broadcast::Receiver<serde_json::Value>` — callers serialize before sending
- Option B: Define a `CaptureEntry` enum in `logging_utils` with serialized JSON, callers convert
- **Option C (simplest)**: Each source registers a `broadcast::Sender<String>` (pre-serialized JSON line). CaptureHandle subscribes to all registered senders.

**Recommended: Option C** — keeps logging_utils dependency-free, each crate serializes its own events.

```rust
impl CaptureHandle {
    /// Register a capture source (pre-serialized JSON lines)
    pub async fn register_source(&self, tx: broadcast::Sender<String>);

    /// Start capturing to file
    pub async fn start_capture(&self, file_path: PathBuf, include_logs: bool) -> Result<(), String>;

    /// Stop capturing
    pub async fn stop_capture(&self) -> Result<(), String>;
}
```

## Build Notes

**No extra build flags required.** The `capture` feature is enabled by `kunki` and `sthalam` in their `Cargo.toml` dependency declarations, so a plain `cargo build` includes capture support. The broadcast channels in courier/scribe are always compiled in (near-zero cost when no subscribers — `broadcast::send()` with 0 receivers is a no-op).

This is different from profiling (`cargo build --features profiling`) which is opt-in.
